# 当前样例运行结果分析与代码修正依据

## 1. 已观察到的结果

上传的提交包中测试报告记录：

- 独立记录数：3；
- 派生窗口数：259；
- 类别记录数：`class-A=2`、`class-B=1`；
- 有效验证折数：2；
- 记录覆盖率：`2/3`；
- Accuracy：`0.5`；
- Macro-F1：`0.3333`；
- Weighted-F1：`0.6667`；
- Log Loss：`0.8011`；
- 原报告给出的 Macro-F1 95%区间为 `[0, 1]`。

## 2. 不能直接得出的结论

259个时间窗口来自3条独立记录，不能视为259个独立训练样本。当前 `class-B` 只有一个批次：

- 将该批次留作测试时，训练折中不存在 `class-B`；
- 为避免类别泄漏，该折必须跳过；
- 实际独立验证只覆盖 `class-A`，类别覆盖率为50%；
- 因此 Accuracy、Macro-F1和Log Loss只能作为诊断值，不能作为完整比赛性能；
- 仅基于2个独立测试记录计算置信区间没有统计解释价值。

## 3. 本次代码修正

1. 评价状态不再只根据“有效折数”判定为 `ok`，而是同时检查记录覆盖率和类别覆盖率；
2. 当某类别没有独立测试预测时，状态改为 `insufficient_class_coverage`；
3. `eligible_for_primary_score=false` 时，报告明确将指标标记为“仅诊断”；
4. 输出雷达、红外、融合三个分支的消融指标，避免在证据不足时盲目调整固定融合权重；
5. 小样本时增加概率平滑，只降低不可靠的置信度，不改变预测类别排序；
6. 置信区间仅在类别覆盖完整且独立测试记录数达到阈值后计算；
7. 最终提交包纳入完整 `evaluation/`、模型摘要、模型卡和SHA-256清单；
8. 新增提交包自动校验，防止报告中引用的指标文件未实际打包。

## 4. 后续数据要求

代码不会通过随机拆分同一记录的窗口制造更高分数。要获得可解释的比赛性能，应优先补充独立批次，至少保证每个类别可以在保留测试批次后仍出现在训练集中。完整数据到位后，分支消融结果才适合用于自动或人工调整融合权重。
